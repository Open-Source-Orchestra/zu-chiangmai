# ZU / CHIANG MAI — the self-updating Chiang Mai agenda

Official living field guide and memory PIT: **https://zuchiangmai.app/** — a read-only, mobile-first, no-tracker agenda of public 4Seas / ETHChiangmai-season gatherings in Chiang Mai, with a 16-milestone season rail and the in-app `/pit/` memory archive. By the ʻohana — Shaka's AI family.

## How it stays fresh (since 14 Nov 2026)

| what | how often | who |
|---|---|---|
| live listings in the browser | every ~120 s / on "Refresh sources" | the read-only `zu-chiangmai-schedule` Worker (60 s edge cache, stale-last-good) proxies the public 4Seas listings |
| the static bundle in `public/` (no-JS agenda, per-event `.ics`, counts, search index, sitemap) | **daily 08:00 Asia/Bangkok** | **AGENDA KEEPER 🗓️** (a cheap scheduled agent) runs `builder/refresh.py` → diff → commit → outbox |
| deploy to Cloudflare | after every keeper commit (and on demand) | the Admiral's office runs `builder/deploy.sh` (fail-closed checks → wrangler → 9-check hero test + smoke test → rollback on failure → push) |
| the daily digest to Shaka | daily, once | the keeper emails: listings count, +added −removed ~changed, next 3 events, deployed yes/no, Road-to-2027 next stop; same line in `/shared/heartbeat/pulses/agenda-keeper.md` |
| reviewed milestone rail (`builder/data/program-milestones.json`), hero photos, PIT | when a human edits them | you — see below |

**Fail-closed law:** `refresh.py` refuses (exit 3) to publish an agenda with fewer than 80 % of the previous listings, and `deploy.sh` refuses to ship a bundle with fewer than 80 % of what production serves. Parse/build errors exit 2. Nothing empty or shrunken ever goes live without a human `--force`.

## Editing the agenda in Cursor (or any editor)

```sh
git clone https://github.com/Open-Source-Orchestra/zu-chiangmai.git
cd zu-chiangmai
# 1. edit the human-reviewed data:
#    builder/data/program-milestones.json   ← the 16-milestone ETH / Longevity season rail (dates, titles, source URLs)
#    builder/data/hero-photos.json          ← hero photo provenance (© 4Seas.org, used with permission — do not add other photos)
#    builder/lib/templates.mjs              ← wording / layout of the no-JS page
# 2. preview locally (fetches the public sources, writes a noindex preview):
node builder/build.mjs /tmp/zu-preview && python3 -m http.server -d /tmp/zu-preview 8080
# 3. dry-run exactly what the keeper will do (diff summary, no writes):
python3 builder/refresh.py --dry-run
# 4. commit + push to main
git commit -am "milestones: …" && git push
```

**Then nothing else:** the AGENDA KEEPER pulls `main` at its next 08:00 Bangkok run, rebuilds, and the Admiral deploys; or ping the Admiral (sysadmin 🫡) to run `builder/deploy.sh` right away. Do **not** hand-edit `public/` (it is generated; the only hand-maintained part is `public/pit/`), do not add tokens or `.env` files (none are needed to build), and keep the 4Seas photographs exactly as licensed.

Live listings are *not* edited here — they come from the public 4Seas / ETHChiangmai SocialLayer group; corrections go to the event source (each card links to it).

## Layout

- `public/` — the exact production bundle served by the `zu-chiangmai-site` Worker (apex + `www`). Generated by `ZU_PRODUCTION=1 node builder/build.mjs public` (which is what `refresh.py` runs); `public/pit/` is a first-class native route maintained separately.
- `builder/` — generator (`build.mjs`, `lib/`, `client/`), reviewed data (`data/`), the daily lane (`refresh.py`, `outbox.py`, `deploy.sh`, `tests/`), the read-only schedule Worker source (`worker/`), and `README.md` with the full source/privacy policy.
- `deploy/wrangler.jsonc` — assets-only configuration of the static-site Worker (no secrets; the token lives only in the Admiral's private workspace).

The separate `zu-chiangmai-schedule` API Worker is independent and is **not** redeployed for static-site changes.
